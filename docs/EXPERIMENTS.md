# 实验记录：从通关到无伤，以及没有奏效的尝试

本文记录截至 **2026 年 11 月 2 日** 的训练探索和收尾结论。它保留成功、失败和证据不足的部分，避免把一个成功视频当成稳定胜率，也避免把不同角色配置、动作空间或机器上的结果混成一次实验。

关键数值另存于 [experiment_results.json](experiment_results.json)。日常运行方式与清理后的实机验收见 [项目 README](../README.md)。下面的表格已包含理解实验所需的结果，不要求读者拥有本机完整训练目录。

## 1. 先统一角色配置，再比较模型

早期训练曾出现**实际骨钉单刀 33 伤害**的配置，没有按后来约定的“满级骨钉 21 伤害、无战斗护符”统一验收。因此，早期的调谐通关和辐辉记录只能作为旧配置实验，不能冒充标准 21 伤害条件下的结果。后来单独修复、分发并重新加载了四个游戏实例的训练存档，避免把旧配置样本混入新训练。

本文后续的 550、650 和离散策略均属于纠正配置后的实验：

| 项目 | 条件 |
|---|---|
| Boss | 叛徒领主，原生辐辉难度，初始 1300 HP |
| 骑士 | 初始 9 格生命、0 蓝血、0 SOUL；辐辉按原生规则一次有效受伤即死 |
| 骨钉 | 满级骨钉，实测单次命中 21 伤害 |
| 法术 | 黑波、黑吼、黑砸，均为升级版；从正常骨钉命中获取 SOUL |
| 护符和其他动作 | 无战斗护符；保留存档中的虚空之心。不使用回血和剑技 |
| 运行 | 1 倍速；场景重置后重新确认难度和初始资源 |

这里的“9 格生命”不代表辐辉能承受九次伤害。死亡时观测可能从 9 变成 0，日志中的 `damage=9` 是损失的生命格数，不是受到九次攻击。

曾通过实际命中观察到黑波造成 **30 点伤害**，并通过施法检查确认三种法术会正常消耗 SOUL。黑吼和黑砸当时的独立检查未保存完整的有效命中伤害序列，不能据此声称已经逐段证明它们的所有伤害常量。无伤录屏也没有保存每一次攻击的完整伤害轨迹；角色配置审计、终局日志和录像是不同层次的证据。

## 2. 训练、评估和录屏的口径

- **训练**按策略分布随机采样动作，再用新采集的数据进行 PPO 更新。
- **固定权重评估和录屏**使用贪心动作，不更新权重和观测归一化。
- 一次 **episode** 是一次结束的 Boss 战；一次 **update** 是收集一批状态转移后的一次 PPO 更新，其中包含多轮小批量优化。二者没有固定的一对一关系。
- 10 Hz 是名义决策频率，不是游戏画面帧率。16 帧堆叠保存最近 16 次状态观测，也不是 16 张连续截图。
- 最终实验的名义战斗预算为 150 秒，观测中的时间尺度仍为 60 秒。截止判断按决策步数乘名义步长计算，实际墙钟时间还会受通信和执行开销影响。
- 失败后一直重试、首次成功即停止，可以证明模型能完成任务；这样的录像选择流程不能当成预先固定局数的胜率测试。

多实例训练的 Python、神经网络推理和优化器都运行在 A 主机，B 主机提供远端游戏实例。550 和 650 都是共享策略，所谓“B 主机的权重”实际指的是“该模型的历史无伤出现在 B 端口”，不是 B 单独训练出的另一套网络。

## 3. 保留下来的标准奖励

21 伤害、三法术实验后期使用的奖励如下。表中是进入 PPO 缩放前的数值；PPO 统一再乘 `0.05`。

| 事件 | 原始奖励 |
|---|---:|
| Boss 实际掉血 | 掉血量 ÷ 21 |
| 击败 Boss | +100 |
| 一次被跟踪的 Boss 招式动作结束，期间无受伤 | +0.1 |
| 确认骨钉空挥 | −0.005 |
| 时间成本 | −0.1 / 名义游戏秒 |
| 安全接近阶段离 Boss 过远 | 最多 −0.15 / 名义游戏秒 |
| 损失生命 | −3 / 格 |
| 死亡 | −20 |

伤害奖励读取 Boss 实际 HP 变化，骨钉和法术统一计分；没有因为“请求施法”或“花掉 SOUL”就直接加分。正常 21 伤害一刀为 +1，黑波若造成 30 点实际伤害则为 `30/21`。

上述小额闪避奖励确认的是**观察到的招式动作结束**，不能证明飞出的冲击波或其他危险物已经消失。它没有每局五次的上限，也没有被表述为可靠的危险解除检测器。距离惩罚在危险阶段和邻近危险物存在时有豁免，目的是减少长期逃跑，同时保留拉开距离的空间。

辐辉死亡时 9→0 的生命损失与死亡项合计约 **−47**，这是两项奖励叠加的结果。它不是九次独立受伤，也不能据此推断应继续加大死亡惩罚。最终标准分支未开启冲击波专项奖励、攻击距离潜势或 TTC 安全潜势。

## 4. 尝试过什么，结果能说明什么

| 尝试 | 已保存的观察 | 可以得出的结论 |
|---|---|---|
| 换 Boss、增加并行实例、快速场景重置 | 调谐级通关变得可行，采样等待明显减少 | 环境难度与采样效率影响很大；没有完整的同条件计时，不能把“约四倍”当严格基准 |
| 降低熵系数 `0.005 → 0.001` | 早期旧配置调谐复测中，低熵 39/40、对照 37/40 | 是小规模筛查，不能推广为标准 21 伤害辐辉的稳定改进；没有一律采用更低熵 |
| 冲击波期间保持某个距离 | 曾使用距离区间专项奖励 | 没有建立它能可靠降低冲击波死亡率的证据，后来撤下 |
| 真正穿过冲击波后 +1，每局最多 +2 | 旧 33 配置的一次 40 局筛查：候选 0 胜、平均剩血 369.4；对照 2 胜、平均剩血 335.75 | 该轮未显示收益，未作为最终奖励；不能因此证明所有穿波奖励都无效 |
| 通用招式结束无伤奖励和极弱空挥惩罚 | 标准配置的 40 局对照：候选/对照均 0 胜，平均剩血 440.95 / 433.70 | 没有明确胜率收益；后续保留了小额项，不能把后来成功单独归功于它 |
| 只更新冲刺相关参数 | 做过有限分支探索 | 没有形成足以支持稳定无伤提升的结果，没有作为最终训练路线 |
| 攻击位置潜势与预计碰撞时间 TTC 潜势 | 增加了 `γΦ(s')−Φ(s)` 塑形，同时扩展了黑冲等详细输入；该分支表现未达到预期，随后回退 | 这些变化混在同一分支，无法单独证明势函数或新增字段谁导致下降，也不能否定潜势塑形这个方法本身 |
| 新增黑冲可用性、冷却和无敌时长等详细字段 | 与潜势分支一起试用，随后撤回新增输入 | 旧输入本来已有黑冲是否可用的信息；没有独立消融证明详细字段有害 |
| 原输入从 4 帧扩到 16 帧 | 从加入潜势之前的旧 550 恢复，回到原始输入和奖励，只扩展历史；650 后来在 A 录屏成功 | 证明这条路线可用，不证明“帧越多一定越好”或成功完全来自帧数 |
| 连续冲刺请求每次重发 | 同一 550 权重固定试打 40 局：原执行器 1 胜、平均剩血 482.825；重发组 0 胜、489.075 | 消除了某种请求不再发新按键边沿的情况，但该轮没有显示实战收益，默认执行器未切换 |
| 低 SOUL 时不下发法术、避免覆盖普攻方向 | 同一权重 40 局：0 胜，平均剩血 408.725 | 平均输出有变化，仍不足以证明无伤收益；没有与冲刺重发一起混改 |
| 35 个离散动作 | 新增 295 次 PPO 更新、529,920 条训练样本后仍无通关 | 在本次预算内没有实现预期的无伤突破；离散化并非立刻奏效 |

早期 33 配置和后来的标准 21 配置在表中明确分开。不同分支的奖励、训练预算、端口组成和模型都可能不同，这张表是实验纪实，不是严格控制全部变量的排行榜。

### 4 帧到 16 帧的迁移

保留每帧 118 个原始特征时，网络输入由 `4×118=472` 变为 `16×118=1888`；隐层仍为两层 256。扩展的是输入历史，不是把隐层直接改成 512 或 2048。

迁移将旧权重放到对应的最近四帧列，新增历史输入列初始权重为 0，并复制对应的归一化统计。离线检查的 64 个贪心样本没有动作不一致，512 个样本的最大 FP32 logit 差约 `5.72e-6`，符合更宽矩阵乘法的累加精度变化。这个检查说明迁移当下基本保留了旧策略，不代表继续训练后策略仍不变，也不保证更长历史一定提高成绩。

### 35 个离散动作的迁移

离散版每次从一个 35 分类头选一个动作，而原版多个动作头可组合输出。35 个动作由以下类别组成：

| 类别 | 数量 |
|---|---:|
| 不操作、左右移动 | 3 |
| 原朝向/向左/向右跳跃 | 3 |
| 三种朝向 × 水平/向上/向下骨钉攻击 | 9 |
| 上述骨钉攻击同时跳跃 | 9 |
| 原朝向/向左/向右冲刺 | 3 |
| 上述冲刺同时跳跃 | 3 |
| 原朝向/向左/向右黑波 | 3 |
| 黑吼、黑砸 | 2 |
| **合计** | **35** |

它从旧 550 初始化骨干和价值网络，将旧策略在这些固定按键向量上的联合概率条件化，解析构造新的动作头；不是完全随机从零开始，也不等于保留了原版所有动作的分布。迁移初次重置了 Adam，之后三窗/四窗续训保留完整模型、Adam 和归一化状态。删掉动作组合可能减少无效探索，也可能删掉旧策略会用的有效组合，所以不能预设必然优于原版。

## 5. 550、650 与 A/B 主机的证据

两份经常提到的模型实际上不同：

| 模型 | 动作与历史 | SHA-256 |
|---|---|---|
| 原版 550 | 组合动作，4 帧 | `7ac14df0a95ef4fd191ade3e51ee19f94f7383587fc3a9107e826f86d4dd7104` |
| 原版 650 | 组合动作，16 帧 | `9d04b34b66a958d1f1d582710863de7a10e2bb2de6e0082afe7b9a0687c7f68d` |

下列评估固定权重、每台主机各两个实例，各完成 20 局。平均剩血越低表示输出越多。

| 固定评估 | A 无伤 | B 无伤 | A 平均 Boss 剩血 | B 平均 Boss 剩血 |
|---|---:|---:|---:|---:|
| 原版 550，历史评估 | 0/20 | 2/20 | 398.20 | 397.55 |
| 同一 550，同一原执行器独立复测 | 0/20 | 1/20 | 397.20 | 568.45 |
| 原版 650，历史评估 | 2/20 | 0/20 | 453.00 | 468.75 |

550 后来在 A 的一个实例进行了四段录屏试打，分别 132、134、34、109 局，合计 **409 局没有无伤通关**，最好曾剩 29 血。四段使用同一份 550 文件，未发现拿错权重。

650 的两次 A 单实例录屏分别在第 **23 局和第 31 局**无伤通关。胜局分别有 885 和 569 次决策，记录均为原生辐辉、Boss HP 0、受伤统计 0、统计有效且无截断；权重和归一化保持不变。这证明 650 能在 A 反复复现成功，但不能将首次成功即停的两段录像当成稳定胜率估计。

这些记录也没有证明 A 的平均作战能力普遍低于 B：550 原评估的 A/B 平均剩血几乎相同，独立复测里 A 平均输出反而更高。无伤关注的是整场都不犯错，平均输出和稀有的完整成功是不同指标。

### 已确认的执行条件差异

本轮只读审计核实了**启动配置确实不同**：A 两个实例请求 60 FPS，B 两个实例请求 30 FPS；两台均为 1 倍速、640×360。A 保存的图形设置也是目标 60、垂直同步关闭。更新包保留 B 旧启动参数，不会自动复制全局图形设置，因此旧帧率差异能跨 Mod 更新继续存在。

这不是运行中实测 FPS。Mod 在启动时设置上限，游戏菜单可能再次修改帧率和垂直同步；B 当时的菜单值和实际加载游戏/Mod 文件哈希也未完整核实。

在同一 550、原执行器的一次历史长样本轨迹中，A 两实例的决策间隔均值约为 **104 ms**，B 约为 **110 ms**。每步串行命令越多，远端的额外开销越明显。旧轨迹使用的 Windows 单调时钟单个间隔有量化现象，因此这里报告长样本近似均值，不把每个时间戳当微秒级测量。

输入命令通过同步 TCP 请求发送，游戏在 Unity `Update` 中应用；约 60 ms 的按键脉冲在 30/60 FPS 下会跨过不同数量的游戏帧。控制器发送命令后再等待约 100 ms，没有按固定引擎帧数推进游戏。因而相同模型和名义 10 Hz 不代表完全相同的输入生效时机。

另外发现一个两边共有的限制：恢复游戏并等待速度稳定约 150 ms 后，首个决策仍可能使用恢复前保留的暂停观测。状态协议没有引擎帧序号或时间戳来保证新鲜度。它是已知时序问题，**尚未证明是 A/B 无伤差异的原因，也没有把修复混进现有模型**。

因此，可以确认“执行条件不一致”，可以把帧率配置和有效控制时序列为可信候选原因；目前没有做同一主机稳定 30/60 FPS 的交叉试验，也没有统一两台实测 FPS 后重新评估，不能宣称已证明它们就是 550 迁移失败的唯一原因。

## 6. 离散版最终结果

离散版从原版 550 的计数继续编号，最终保存编号为 845。**实际新增更新数是 `845−550=295`，不是 845 次离散训练。**

| 统计项 | 最终值与口径 |
|---|---|
| 新增 PPO 更新 | 295 |
| 已用于更新的新增状态转移 | `1,658,368−1,128,448=529,920`；不包含旧训练样本和评估 |
| 完整结束的训练战斗日志 | 1,335 局，0 胜 |
| 最终检查点中的战斗计数净增 | `4,595−3,266=1,329`；另有 6 局结束后未进入最终保存的更新 |
| 固定权重评估已结束战斗 | 374 局，0 胜：10 轮完整评估共 360 局，另有一轮中断前完成 14 局 |
| 随机训练中单局最好 | Boss 剩 77 HP，未击杀 |
| 固定评估中单局最好 | Boss 剩 136 HP，未击杀 |
| 最后四窗分支的最佳完整评估 | 编号 825，40 局、0 胜，平均 Boss 剩 525 HP |

六局计数差来自两次切换/停止时已经结束、但未纳入最终保存更新的战斗；它们是实际打过的局数，不能据此多算已应用的 PPO 样本。

离散路线在这次有限预算内没有优于已经录成视频的原版组合策略。它提供了清楚的动作语义和可分析的日志，但不能从这些结果断言离散动作普遍无效，或只要再训练一段时间就必然成功。最终按用户要求停止，没有自动继续长训。

## 7. 没有实施的方案与收尾边界

讨论过、但未混入最终训练的方案包括：

- 将 `γ=0.9955` 单独提高到 `0.999` 的长期回报对照。
- 允许少量失误后逐步收紧到一次受伤即结束的训练课程。
- 针对冲击波或碰撞局面的可靠专项初始化和练习。
- 带引擎帧序号、状态时间戳、输入执行确认或同步推进的协议。
- 核实实际 FPS 后，在同一主机按稳定 30/60 FPS 交叉比较，再统一两台条件复测。

这些是后续研究方向，不是本项目已经证明有效或已经完成的功能。最后保留成功模型、标准配置和实验结果，不再通过混加奖励或更换动作空间来追逐一次成功录像。
